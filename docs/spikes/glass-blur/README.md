# 玻璃「模糊」标定台

**问题**：`clam-nativeify` 的玻璃按钮把描边、高光、暗带都对着系统调过了，唯独
**没有背景模糊**——放在花哨背景上就是一块贴纸。系统那层模糊到底是多大的核？

**答案**：**σ ≈ 13pt 的高斯 + 饱和度 ×1.97**，且**不随控件尺寸缩放**。

```sh
docs/spikes/glass-blur/run.sh            # 编译并打开（约 3s），产物在 build/，已 gitignore
docs/spikes/glass-blur/run.sh --dark     # 深色
docs/spikes/glass-blur/run.sh --hold     # 反复抢焦点保持激活态（**会把人赶出电脑**，量完就杀）
pkill -f GlassBlurProbe.app/Contents/MacOS
```

## 怎么量的

给玻璃底下垫一条**竖直硬边**（左黑右白）。理想硬边被 σ 的高斯核糊过之后是条
erf 曲线，其 10%→90% 的水平宽度与 σ 成定比：

```
W(10→90) = 2 √2 · erf⁻¹(0.8) · σ ≈ 2.5631 σ
```

判据**只看曲线形状**：玻璃自己的提亮、描边、发光都只是仿射变换（y = a·f(x)+b），
对 10/90 归一化之后的穿越位置没有影响。这正是选它而不是直接拟合的原因。

三个工具，都是同一个套路（`NSImage` → sRGB 位图 → 数数）：

| | 干什么 |
|---|---|
| `scan.swift` | 水平剖面 + 10/50/90 亚像素穿越点 + σ。`--linear` = 先解码回线性光 |
| `patch.swift` | 矩形块逐通道求平均。`--linear` 同上 |
| `rows.swift` | 沿一列找亮块的行区间，用来定位玻璃条在截图里的坐标 |

```sh
tools/shot.sh --app "Glass Blur Probe" --scale 3 .scratch/glass-light.png
docs/spikes/glass-blur/build/rows .scratch/glass-light.png 300      # 先定位
docs/spikes/glass-blur/build/scan .scratch/glass-light.png 200 280 560 960 --linear
```

## 实测结论

**一、σ ≈ 13pt，且不随尺寸缩放。** 三档玻璃条量出来几乎重合：

| | σ（图像 px, 2x） | → pt |
|---|---|---|
| 96pt 面板 | 26.28 | 13.14 |
| 48pt 条 | 26.02 | 13.01 |
| 32pt 条 | 25.88 | 12.94 |
| 无玻璃对照 | **0.34** | — |

对照那行是必要的：它证明背景硬边本身是锐的，展宽全部来自玻璃。
"不随尺寸缩放"和 `client.js` 里量到的"剖面不随尺寸缩放"是同一条事实的两面——
**玻璃的所有度量都是绝对量**，64pt 探针上量到的可以原样搬到 32px 的按钮上。

CSS 的 `blur(<length>)` 参数按规范就是标准差，所以 `blur(13px)` 可以原样填。

**二、系统的模糊在线性光里做。** 直接拿 sRGB 码值扫剖面会得到一条明显不对称的
曲线（暗侧拖长、亮侧收紧），σ 被高估约 2%；解码回线性光之后 50% 穿越点正好
落在几何边界上（实测 760.03，边界在 759.5）。

CSS 的 `backdrop-filter` 是在 sRGB 里做的，**这一条复刻不了**，代价是过渡带比
系统略暗一点。不影响 σ 的选取。

**三、底色的合成确实在 sRGB 里，可以放心用普通 alpha。** 玻璃盖纯黑读 145.0、
盖纯白读 254.0，这条直线预测中灰 127 → 199.3，实测 199.2。两点解出
`rgba(253, 253, 253, 0.5725)`。

（`client.js` 定稿用的是 `rgba(252,252,252,0.5272)`——那是只拿白底一个点校的，
两者在白底上等价，只在深色背景上分得出。要更贴系统就改那一行。）

**四、饱和度 ×1.97。** 模糊会把颜色搅浑，系统靠提饱和补回来，这就是"糊了却不脏"
的来源。四条中间色带逐通道最小二乘：

| 输入 | 玻璃下 | 裸色 |
|---|---|---|
| g180 | 171.4 228.6 175.9 | 110 180 110 |
| b180 | 189.1 189.1 250.8 | 110 110 180 |
| y180 | 224.6 225.0 163.4 | 180 180 110 |
| gray127 | 201.2 201.2 196.5 | 127 127 127 |

按 `out = 0.42745 · sat_S(in) + 145.0` 反解，加权最小二乘得 **S = 1.966**。
网上复刻液态玻璃的教程普遍给 `saturate(180%)`，量出来正好落在同一档。

**为什么色带是中间色而不是纯色**：纯红/纯绿在玻璃的提亮 + 提饱和之后会撞
0 或 255 的天花板，一 clip 就再也解不出系数——第一版用纯色，解出来的 R 通道
是负数。

## 三个会让数据作废的坑

1. **窗口必须是激活的。** 失活窗口里 macOS 把玻璃整个换成一块平色，零结构
   （实测：盖白底 254 → 242，中灰 199 → 193）。截图工具在后台跑，探针一不留神
   就失活。所以有 `--hold`，和右上角那颗激活态指示灯——**红灯的截图直接作废**。
2. **`open` 对已在跑的 app 只会激活旧进程**，改了源码也看不到。`run.sh` 现在
   先 `pkill`（栽过一次：改了色带、量出来还是旧色）。
3. **`tools/shot.sh --scale 3` 给的画布是 3x，但内容按显示器的 2x 渲染在左上角**，
   右边和下边是空白。**倍率要从内容里反推**，别拿画布尺寸除窗口尺寸：这里靠
   "96pt 的条量出来 192px"确认是 2x。搞错倍率 σ 就差 1.5 倍。

## 没有量到的

- **深色档。** 切到 `--dark` 那次的读数自相矛盾（三个中性点严重不共线，
  sRGB 和线性光两种模型都拟合不上），怀疑是外观切换和抢焦点撞在一起了，
  没有复测。`client.js` 里深色沿用同一组 blur/sat——**材质是同一个
  `.glassEffect(.regular)`，翻面的只是那层 tint**，这个推断是合理的但没实测。
- **折射/扭曲（lensing）。** 不追求，没测。
- **自适应染色。** 中灰色带在玻璃下读出 (201.2, 201.2, 196.5)——一个中性输入
  出来偏暖，而且比黑白两点定出的直线高 1.9 级。方向正好是它左邻那条黄色带。
  像是系统还在按一个**大得多的半径**对背景做整体取色。幅度只有 ±3/255，
  CSS 里也复刻不了，忽略。
