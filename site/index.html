Surf is in early development. It follows dsh 0.1.1-rc.2, and it does not update itself yet.

A native Mac app for DeepSeek Harness.

Surf gives dsh a real window — a native session list, real notifications, a settings window, keys that work. The frame around the conversation is Swift, and it can be rebuilt while the app is running.

Version 0.1.0  ·  macOS 27

DeepSeek Harness in a browser tab. The same session, in a window of its own.

Surf is a shell, not a fork. Sessions, settings and themes stay in dsh; Surf projects them into AppKit rather than keeping a second copy.

Where dsh has not built something, Surf says so instead of inventing it. The gaps we ran into are written down in the repository, each with a script to re-check it.

Module names are proposed. The packages in the repository are named surf-*.

The web view stops looking like a web view.

Popovers, button groups and the composer card are drawn with the system’s own materials — and type is pulled back to macOS metrics.

Native code, swapped in while you watch.

A plugin’s Swift directory compiles to a module named after a hash of its own contents, which then claims the slot the previous generation was holding.

SessionsPlugin.swift
// One C entry point. That is the whole ABI.
@_cdecl("surf_plugin_entry")
public func surf_plugin_entry() -> UnsafeMutableRawPointer {
    Unmanaged.passRetained(SessionsPlugin()).toOpaque()
}

final class SessionsPlugin: SurfPlugin {
    func activate(host: SurfHost) -> AnyObject? {
        let handle = SurfPluginHandle()
        host.register(slot: "sidebar") { AnyView(SessionListView()) }.kept(by: handle)
        return handle  // host lets go = this generation retires
    }
}

0.45 s for a six-line view, 1.03 s for the 408-line session list. A compile error keeps the last good generation on screen, with the file and line in the terminal.

A settings window, not a web dialog in a frame.

Five panes of AppKit that load no web content, applying changes as you make them the way Mac settings do.

The first four panes mirror dsh’s own settings pane for pane. The plugin list is deliberately read-only — dsh exposes no way to toggle one, and a switch that does nothing is worse than no switch.

What carries over between sessions.

A folder of markdown files: the index goes in on every step, pinned ones go in whole, and a body is read only when it is needed.

pinned copy-style Short, factual, no reassurance.
native-abi-notes Old images are never unloaded.
toolbar-contracts Metadata rebuilds; traffic updates in place.
release-checklist Notarise twice, staple both, in that order.

No special tools — the agent edits them with the read, write and grep it already has. This is the one plugin here with no macOS in it, so it runs anywhere dsh runs.

Said plainly because it is true: a prompt injection that reaches the write path survives across sessions. That is an accepted residual risk, not a solved problem.

Requires macOS 27

Install dsh, drag Surf to your Applications folder, open it. Surf starts the backend when you open it and stops it when you quit — no Xcode, no toolchain, nothing to configure.
